# Iben Recorder 0.7.2 — перевірки

Дата: 2026-10-04. Версія APK: 0.7.2, versionCode 9.
Базовий проєкт: 0.7.1; applicationId `ua.iben.recorder.oreo` збережено.

## Android-збірка

Середовище: Java 17, Gradle 8.9, Android Gradle Plugin 8.7.3,
Android SDK Platform 35 revision 2, Build-Tools 34.0.0.

Завдання `:app:assembleDebug :app:assembleRelease :app:lintDebug :app:lintRelease`
завершилися **BUILD SUCCESSFUL** на остаточному коді. Debug APK зібрано;
release APK зібрано без підпису. Lint: **0 помилок, 31 попередження** у кожному
варіанті. Перевірки Lint не вимикалися, baseline для приховування нових проблем
не додавався.

| Категорія попереджень Lint | Кількість |
| --- | ---: |
| ApplySharedPref | 10 |
| AppBundleLocaleChanges | 1 |
| CustomX509TrustManager | 1 |
| WakelockTimeout | 1 |
| UsableSpace | 4 |
| ViewConstructor | 1 |
| SetTextI18n | 13 |

CustomX509TrustManager стосується явно імпортованого сертифіката. Код перевіряє
точний DER-збіг кінцевого сертифіката, його строк дії та викликає платформний
TrustManager з окремим сховищем довіри. Стандартна перевірка імені сервера
HttpsURLConnection залишається. Глобальні SSL/hostname defaults не змінюються.
Попередження залишено видимим; наведені нижче TLS-тести перевіряють поведінку
JVM, але не є сертифікацією TLS-реалізації кожної прошивки Android.

Архів містить вихідний код, **без APK, приватних ключів або паролів**.
Для встановлення поверх своєї попередньої версії використайте той самий ключ
підпису. Gradle запускайте на JDK 17; Java 8 у compileOptions — рівень мови.

### База записів

У 0.7.2 схема залишається v5; нової міграції немає.
`tools/check_database.py` витягує фактичні SQL-команди з RecordIndex.java та
виконує їх на SQLite. Перевірені міграції **v1/v2/v3/v4 → v5** зі збереженням
усіх старих полів, станів файлів, квитанцій SHA-256, віддалених імен, історії
прослуховування й журналу видалення окремих підключень.

Перевірено збереження важливості, часових позицій і Unicode-приміток закладок
після закриття та відкриття дискової бази, порядок закладок, а також відокремлення
метаданих різних записів. Це перевірка SQL і даних; Android SQLiteOpenHelper
на пристрої не запускався.

### Мережа

122 перевірки WebDAV використовують реальні HTTP-запити на loopback
з тестовим транспортом. Для передачі залишено перевірку SHA-256 завантаженого
аудіо. Для видалення перевірено новий шлях HEAD → DELETE з If-Match:

- точну назву, зокрема Unicode, і збіг Content-Length;
- один HEAD та один DELETE для успішного видалення;
- нуль GET і нуль байтів аудіо у відповідях під час видалення;
- три послідовні видалення: три HEAD і три DELETE без читання аудіо;
- відмову при іншому розмірі, відсутньому розмірі, слабкому/відсутньому ETag;
- відмову при непідтримуваному HEAD без переходу на повне завантаження;
- конфлікт, коли ETag змінився між HEAD і DELETE;
- скасування до HEAD, після HEAD та зміну дозволу на видалення;
- помилки сервера, втрату відповіді DELETE та безпечний повтор після 404;
- збереження попередніх перевірок PUT, колізій і заборони redirect із паролем.

Перевірка за назвою та розміром свідомо слабша за порівняння вмісту: підміна
іншим вмістом такого самого розміру до HEAD не виявляється. Окремий тест
фіксує саме цю поведінку. Поточний ETag захищає від зміни між HEAD і DELETE,
але не порівнюється з історичною версією під час завантаження. Дата створення
на сервері не використовується. Заголовки та TLS мають мережеві накладні витрати;
«нуль байтів аудіо» не означає відсутності мережевого трафіку.

Перевірки TLS використовують справжній локальний **HTTPS-сервер** та
звичайний production-конструктор DavClient. Тимчасові RSA-сертифікати створюються
`keytool` і прибираються після тесту. Перевірено:

- PEM і DER, збіг показаного SHA-256;
- відмову для приватного ключа, кількох сертифікатів, порожнього/завеликого файла;
- відмову для простроченого сертифіката при імпорті й використанні;
- передачу, зворотну перевірку та умовне видалення з точним імпортованим сертифікатом;
- відмову для self-signed без імпорту, іншого сертифіката та неправильного hostname;
- відсутність HTTP-запитів з обліковими даними при невдалій TLS-перевірці;
- збереження локального аудіо та відсутність глобального послаблення довіри.

Політика HTTP перевірена для приватних діапазонів і їх меж; публічні IP, DNS,
loopback, link-local, IPv6, неоднозначні адреси, URL із credentials, query,
fragment і traversal відхиляються. HTTP без явного дозволу відхиляється.
Канонічний ключ старого HTTPS-підключення не змінився.

Фактичної передачі по HTTP до окремого пристрою в LAN не виконано: політика адрес
перевірена напряму, а мережевий обмін — на локальних тестових серверах.

## Перевірка змін 0.7.2

Повна Android-збірка перевірила нові векторні ресурси, виклики View/ImageButton,
діалоги довідки, підключення змін закладок до шкали та інтерфейси обробників.
Переклади нових підказок перевірено для трьох мов. Нових залежностей немає.

Під час перегляду коду перевірено всі входи до групового вибору: кнопку, вибір
дня й контекстне меню. Картка програвача приховується, відтворення звільняє файл,
одиничні дії блокуються, а довге натискання не показує їхнє меню. Завершення
вибору відновлює програвач без автозапуску. Кнопка групових дій недоступна без
вибраних файлів. Це перевірка коду, не автоматизований тест натискань на Android.

Позначки читаються із SQLite у наявній черзі фонової роботи, лише при відкритті
запису та після змін. Обробник перевіряє ID запису й номер запиту, щоб запізніла
відповідь не нанесла позначки попереднього запису. Малювання та таймер програвача
не читають базу. Вікно масштабу використовується і для малювання, і для переходу
натисканням. Близькі прапорці можуть накладатися; текстовий список закладок дає
доступ до кожного з них. Позначки доступні й до завершення аналізу хвилі.

Вигляд, натискання, TalkBack, масштабування шрифтів і переходи за прапорцями
потребують перевірки на телефоні за новими сценаріями в README.

## Межі перевірки

Не виконано запуску 0.7.2 на фізичному телефоні або емуляторі. Не перевірено
багатоденний запис на J7, поведінку Samsung, стики реального AAC, Android Keystore,
системний вибір папки/експорт, вигляд групового вибору й діалогів на екрані телефона.
Групові UI-операції та прив’язка закладки до фактичного звуку потребують ручної
перевірки за сценаріями README. Тест конкурентної позиції не замінює тест кодека.

Сервер користувача не підключався; його файли не змінювалися. Не перевірено кошик,
права, ETag і особливості реального Nextcloud або іншого WebDAV-сервера.
Фактичний час видалення й економію трафіку на сервері користувача не вимірювали.
Автоматичні тести й успішна збірка не гарантують сумісності з кожною прошивкою
Android 8.1–16 або кожним WebDAV-сервісом.
