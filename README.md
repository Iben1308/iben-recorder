# Iben Recorder 0.7.0 — Android 8.1+

Автономний аудіореєстратор для Samsung J7 2016 та новіших телефонів.
Три вкладки: **Слухати / Запис / Налаштування**. Українська, англійська та польська
мови; світла й темна теми. Google Play Services, GApps і сторонній клієнт хмари
не потрібні. Розпізнавання мовлення, реклама й моніторинг батареї не додаються.

Архів містить **вихідний проєкт Android Studio**, а не підписаний APK.
Debug/release зібрані, автоматичні тести та Android Lint пройдені; подробиці —
у [VALIDATION.md](VALIDATION.md). **0.7.0 ще не запускалася на фізичному телефоні
або емуляторі.** Багатоденну роботу потрібно перевірити на своєму J7.

## Нове у 0.7.0

### Важливі записи

Виберіть запис і натисніть **«Позначити важливим»**; така сама дія є після
довгого натискання на рядок. Зірочка позначає важливий запис. У списку є фільтр
**«Важливі»** разом із «Усі / Непрослухані / Прослухані».

- Автоматичне очищення не видаляє важливі записи, навіть якщо їх передано у хмару.
- Групове видалення пропускає важливі записи на телефоні й у хмарі.
- Одиничне ручне видалення можливе після підтвердження з окремим попередженням.
- Групове зняття важливості теж потребує підтвердження.

Важливі файли входять до ліміту пам’яті. Якщо вони разом із непереданими файлами
заповнять доступне місце, запис зупиниться: захист файлів має пріоритет.
Закладка сама по собі не захищає файл від очищення — для цього поставте зірочку.

### Закладки

**«＋ Закладка»** доступна під час запису та у програвачі. Момент зберігається
одразу; після цього можна додати примітку до 160 символів. Закриття діалогу
примітки залишає закладку без тексту. Закладка під час запису прив’язується до
останнього записаного аудіокадру конкретного фрагмента, включно з моментом поділу.

У програвачі відкрийте **«Закладки»**: натискання переходить до відповідного часу;
довге натискання дозволяє редагувати примітку або видалити закладку.
Закладки й важливість зберігаються локально в SQLite, не змінюють M4A та його
назву й не передаються через WebDAV. Видалення локального запису прибирає його
закладки. Видалення лише хмарної копії залишає локальні позначки.

### Групові дії

У «Слухати» натисніть **«Вибрати записи»**. Можна вибирати окремі рядки,
натиснути заголовок дня або вибрати всі записи поточного фільтра. Довге
натискання на день одразу відкриває вибір цієї групи. Зміна фільтра очищає вибір.

Кнопка **«Дії»** дозволяє:

- позначити прослуханими / непрослуханими;
- поставити / зняти важливість;
- експортувати аудіофайли до папки через системний діалог Android;
- видалити лише з телефона, лише з хмари або з обох місць.

Перед видаленням показуються кількість, загальний розмір, кількість важливих
записів, які буде пропущено, і вибране місце видалення. Перед видаленням
непереданих локальних копій показується попередження.

Обробка послідовна, з прогресом, скасуванням і підсумком: виконано, пропущено,
помилок, не оброблено. **Тримайте застосунок відкритим до завершення.** Згортання
або вихід із застосунку скасовує решту операції. Уже виконані дії не відкочуються;
запит DELETE, який дійшов до сервера, може завершитися навіть після скасування.
Незавершену групу після перезапуску потрібно вибрати знову.

Експорт створює незалежні копії аудіо без локальних позначок і закладок. Якщо
назва вже зайнята, до нової копії додається UUID. Застосунок не перезаписує
вибрані раніше копії навмисно; поведінка системного постачальника документів
також залежить від Android. При помилці копіювання новий неповний документ
видаляється за можливості. Після аварійного завершення процесу перевірте папку
експорту: неповна копія могла залишитися.

Для старих записів важливість спочатку вимкнена. HTTPS-підключення зберігають
свою попередню ідентичність; нові дозволи HTTP і власний сертифікат не вмикаються
автоматично. Повернення до старого APK із базою v5 не підтримується.

Wrapper JAR в архів не включено. Можна створити Wrapper встановленим Gradle 8.9
або скористатися `build.sh` (Linux, JDK 17, Python 3.11+, налаштований SDK):

```bash
cd /home/iben/Android/project/iben-recorder-android81
bash tools/check.sh
bash build.sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`tools/check.sh` потребує повного JDK із `keytool`; тимчасові тестові сертифікати
створюються й видаляються автоматично. Ці тести не звертаються до вашої хмари.
`build.sh` завантажує офіційний Gradle та перевіряє SHA-256. Першій збірці потрібні
інтернет на комп’ютері й прийняті ліцензії Android SDK. Шлях SDK береться з
`ANDROID_SDK_ROOT`, `ANDROID_HOME` або `$HOME/Android/Sdk`.

Проєкт Android 10 `j7-recorder` з пакетом `ua.iben.recorder` — інша лінійка.
Цей архів оновлює `.oreo`; дані іншого пакета автоматично не об’єднуються.

## Хмара / WebDAV

Усі основні назви й статуси узагальнено до **WebDAV**. Рекомендований приклад —
**Nextcloud**, але клієнт може працювати з іншими сумісними WebDAV-серверами.

Потрібні повна кінцева адреса вже створеної папки, логін і пароль або пароль
застосунку. Використовується HTTP Basic authentication. OAuth, інтерактивний
вхід через сайт, клієнтські TLS-сертифікати та публічні посилання «Поділитися»
не реалізовані. Сервер має підтримувати GET, PUT, DELETE, умовний PUT
`If-None-Match: *`; для безпечного видалення потрібні сильний ETag і `If-Match`.
Тому сумісність не гарантується з кожним сервісом, який називає себе WebDAV.

### Налаштування

1. Створіть на сервері папку з правами читання й запису, наприклад `recordings`.
2. Відкрийте **Налаштування → Хмара / WebDAV → підключення**.
3. Введіть повну адресу папки, логін і пароль. Приклад:
   `https://server.example.com/recordings/`.
4. Натисніть **«Перевірити підключення»**: тест створює, читає, звіряє й видаляє
   лише власний маленький тестовий файл. Після обриву він може залишитися на сервері.
5. Увімкніть автопередачу, за потреби залиште «Лише мережа без тарифікації» та
   натисніть **«Зберегти підключення»**. Кнопка перевірки сама не зберігає поля.

Порожнє поле пароля зберігає наявний пароль лише для тієї самої адреси й логіна.
Для нового підключення, зокрема переходу HTTPS → HTTP, пароль треба ввести знову.
Пароль зберігається зашифрованим AES-GCM; ключ — в Android Keystore. Пароль не
потрапляє до журналу, системне резервування даних застосунку вимкнене.

### Nextcloud як приклад

У Nextcloud створіть папку `IbenRecorder81`. У налаштуваннях розділу «Файли»
скопіюйте WebDAV-адресу та додайте назву папки. Приклад:

```text
https://cloud.example.com/remote.php/dav/files/LOGIN/IbenRecorder81/
```

Якщо сервер установлено в підкаталозі, збережіть цей підкаталог в адресі.
У **Особисті налаштування → Безпека** створіть окремий пароль застосунку.
Введіть його на телефоні. Окремий Android-клієнт Nextcloud не потрібний.

### Локальний HTTP без сертифіката

Є окрема опція **«Дозволити HTTP у локальній мережі — не рекомендовано»**.
Вона початково вимкнена й потребує підтвердження: **аудіо, логін і пароль
передаватимуться без шифрування**. Використовуйте лише в довіреній мережі.

Підтримано лише числові приватні IPv4-адреси: `10.x.x.x`, `172.16.x.x`…`172.31.x.x`
або `192.168.x.x`, наприклад `http://192.168.1.20:8080/recordings/`.
Домени, публічні IP, IPv6, loopback, link-local та неоднозначні числові форми для
HTTP не приймаються. HTTP-з’єднання не використовує налаштований системний проксі.

Спочатку введіть адресу й логін, потім підтвердьте HTTP. Редагування цих полів
скидає дозвіл; збережений дозвіл прив’язаний до конкретного підключення.
Помилка HTTPS не перемикає клієнт на HTTP. Перенаправлення не виконуються.
Android manifest дозволяє cleartext на рівні платформи для цієї функції;
фактичний доступ обмежує перевірка адреси в клієнті.

### HTTPS із власним або самопідписаним сертифікатом

1. Залиште адресу `https://…`. Отримайте **публічний сертифікат саме сервера**
   у PEM або DER: один сертифікат до 64 КіБ, без приватного ключа та без ланцюжка.
2. Натисніть **«Імпортувати сертифікат сервера»**.
3. Звірте показаний SHA-256 із відбитком на своєму сервері та підтвердьте довіру.
4. Перевірте й збережіть підключення.

Довіра діє лише для точно імпортованого сертифіката в цьому підключенні.
Перевіряються строк дії, точний збіг сертифіката та ім’я сервера; перевірка
сертифіката також передається платформному TrustManager з окремим сховищем довіри.
Для IP-адреси в URL сертифікат повинен містити відповідний IP у Subject Alternative
Name; для домену — відповідне DNS-ім’я. Імпорт не виправляє невідповідне ім’я.

Після поновлення сертифіката потрібен повторний імпорт. Зміна адреси або логіна
скидає вибраний сертифікат. Кнопка **«Використовувати системну довіру»** повертає
звичайну перевірку Android після збереження. Глобальна довіра інших застосунків
не змінюється.

## Передача, видалення та ліміт пам’яті

Завершені файли передаються від найстаріших. Після PUT клієнт читає **весь файл
назад** і звіряє розмір та SHA-256. Це додає вхідний трафік приблизно в розмір
файла. Пам’ять RAM не заповнюється всім записом: копіювання потокове.

Черга й підтвердження зберігаються в SQLite, фонову передачу запускає JobScheduler.
Черга працює й після зупинки аудіозапису. Мережеві помилки повторюються з паузами
від 30 с до 30 хв; Android може відкласти запуск довше. Незавершена передача
повторюється цілим файлом. Якщо попередня спроба вже зберегла цілий файл,
повтор спочатку перевіряє його вміст. Колізія назви не перезаписує чужий запис:
для власного файла використовується збережена альтернативна назва з UUID.

Це **одностороннє архівування**. Зміни на сервері не завантажуються назад.
Видалений через інтерфейс сервера файл не перевіряється заново перед кожним
локальним очищенням. Позначки й закладки не синхронізуються.

| Ручна дія | Результат |
| --- | --- |
| Лише з телефона | Видаляє локальне аудіо, історію, закладки й кеш; хмарна та експортовані копії залишаються. Для непереданого файла показується попередження. |
| Лише з хмари | Видаляє перевірену копію поточного підключення. Локальний файл залишається; його повторна передача й автоматичне очищення для цього підключення блокуються. |
| З телефона і хмари | Спочатку підтверджує хмарне видалення, потім видаляє локальний файл. Якщо перший крок не підтверджено, локальна копія залишається. |

Хмарне видалення потребує збереженого підтвердження передачі до поточного
підключення. Перед DELETE перевіряються віддалений вміст, SHA-256 і сильний ETag;
запит має `If-Match`. Інший вміст або відсутність сильного ETag зупиняє дію.
Намір видалення зберігається **до мережевого запиту**, тому збій не спричиняє
повторного завантаження видаленого файла. Після втрати відповіді повторна ручна
спроба перевірить відсутність файла. Автоматичних повторів DELETE немає.

Статус незавершеного або виконаного видалення видно в рядку. Для відновлення
автопередачі: утримайте рядок → **«Дозволити передачу знову»** → підтвердьте.
Ці стани прив’язані до адреси й користувача. Ручне хмарне видалення використовує
поточну мережу навіть при вимкненій автопередачі або її обмеженні лише Wi-Fi.

Зайняті передачею, експортом чи аналізом файли не видаляються. Власне відтворення
перед видаленням зупиняється. Якщо видалення з хмари пройшло, а локальне — ні,
програма показує частковий результат. Кошик і відновлення на сервері залежать
від сервера; WebDAV DELETE тут не очищує серверний кошик.

Список містить **локально наявні записи з реєстру цього застосунку**. Записи,
які залишилися тільки в хмарі, переглядайте й видаляйте через серверний інтерфейс.
Повного браузера хмарного архіву в цій версії немає.

Автоматичне очищення видаляє найстаріші завершені локальні записи з перевіреною
передачею до поточного підключення. Важливі, непередані, активні, зайняті файли
та записи з наміром хмарного видалення захищені. Сторонні файли не видаляються.
Очищення спрацьовує лише за потреби місця; сама успішна передача не видаляє файл.
Захищені файли враховуються в ліміті. Якщо вільного місця недостатньо, запис
зупиняється й повторює спроби після звільнення місця.

## Запис і прослуховування

AAC-LC / M4A, моно, 44100 або 48000 Гц, 64–256 кбіт/с; фрагменти 1–180 хвилин.
Підсилення 0…+24 дБ зі згладжуванням і обмеженням піків. Один AudioRecord і AAC-кодек
працюють протягом сесії; попередній M4A фіналізується окремо, поки пишеться наступний.
Робочі файли приховані в `.temp` і не передаються. Готові мають назву на зразок
`2026-10-03_14-30-00(60_00).m4a`: місцеві дата/час початку й тривалість хв_сек.

Ліміт: 128–32768 МіБ, початково 2048 МіБ; потрібен запас на два фрагменти.
Додатковий резерв накопичувача — 256 МіБ. Пошкоджені `.part` після аварії
залишаються в `.temp` для ручного розбору й займають місце.

Джерела звуку: вибір Android, доступні вбудовані мікрофони, дротова гарнітура
та USB-аудіо. Доступність залежить від прошивки. Зникнення явно вибраного входу
зупиняє запис до повторної спроби; автоматичний режим дозволяє Android змінювати
маршрут. Режим «розпізнавання голосу» — лише режим входу Android, без перетворення
мовлення на текст. Запис дзвінків, внутрішнього звуку й окреме Bluetooth SCO
не реалізовані.

Відтворення: 0,5…2× зі збереженням висоти тону, ±10 с, шкала та масштаб 1/4/16×.
Історія позиції зберігається при паузі, перемотуванні й приблизно кожні 10 с.
Автоматична позначка «Прослухано» потребує досягнення кінця та фактичного покриття
щонайменше 95%; перемотування не зараховує пропущене. Фонове відтворення не
реалізоване: згортання або перехід до іншої вкладки ставить звук на паузу.

Шкала нових записів накопичується під час запису. Старі записи аналізує окрема
служба, що може продовжувати після згортання та має сповіщення зі скасуванням.
RMS-крок — 250 мс; початковий поріг тиші −45 dBFS, діапазон −60…−20 dBFS.
Це індикатор рівня: тихе мовлення теж може позначатись як тиша. Звук не вирізається.
Кеш приблизно до 32 МіБ, локальний; після втрати його можна побудувати знову.

## Розклад і версії Android

У налаштуваннях є підвкладки **Загальні / Звук / Розклад / Хмара–WebDAV**.
Для кожного дня задається один часовий діапазон за часовим поясом телефона.
`22:00 → 06:00` переходить на наступний день; однакові години означають 24 години.
Суміжні діапазони об’єднуються. «Активувати / Призупинити розклад» — одна кнопка;
окрема кнопка збереження годин не змінює стан активації.

Ручний запис не зупиняється через межу розкладу. Ручна зупинка автоматичного
запису пропускає решту поточного діапазону. Для розкладу 24/7 пропуск діє до
повторного збереження розкладу або ручного запуску. Перехід літнього часу
використовує правила Android; восени обирається перший відповідний момент.

| Android | Файли та запуск |
| --- | --- |
| 8.1–9, API 27–28 | Записи в `Music/IbenRecorder81`, потрібен дозвіл на сховище; автоматичний запуск і відновлення після першого розблокування за налаштуваннями. |
| 10, API 29 | Записи в папці застосунку; широкий доступ до файлів не потрібний. |
| 11+, API 30+ | Активуйте розклад у відкритому застосунку. Між інтервалами служба очікує без захоплення звуку. Після перезавантаження або втрати служби потрібне відкриття застосунку чи натискання сповіщення. |
| 12+, API 31+ | Для розкладу потрібен доступ «Будильники та нагадування». |
| 13+, API 33+ | Надайте дозвіл на сповіщення; він потрібний автономному розкладу. |
| 14–16 | Є гілки сучасних обмежень мікрофона й служб; інтерфейс враховує системні панелі. Ця версія не перевірялася на кожній ОС. |

На Android 10+ готові записи містяться в
`Android/data/ua.iben.recorder.oreo/files/recordings/`; робочі файли — у `.temp`
поруч. **Видалення застосунку або очищення його даних видалить ці локальні записи.**
Після переходу самого телефона з Android 8.1/9 на 10+ можна підключити стару
`Music/IbenRecorder81` через відповідну кнопку налаштувань. Копіюються лише
файли з наявного реєстру інсталяції; старі оригінали залишаються й займають місце.

Для розкладу використовується AlarmManager; Android може показувати значок
будильника. На сучасних ОС служба очікування має постійне сповіщення. Системні
обмеження Samsung і квоти JobScheduler можуть затримувати відновлення й передачу.
Вимкніть оптимізацію батареї для Iben Recorder та перевірте довгу роботу на J7.
Після примусової зупинки в налаштуваннях ОС застосунок треба відкрити вручну.

Сповіщення про збій запису/брак місця з’являється одразу за доступних дозволів.
Для повторних помилок WebDAV — під час невдалої повторної спроби після щонайменше
30 хв від першого збою. Очікування Wi-Fi саме по собі не є помилкою. Однакові
сповіщення пригнічуються до усунення проблеми; адреса й пароль у них не виводяться.

## Коротка перевірка на J7 після оновлення

Використайте короткі тестові записи перед переходом до багатоденної роботи:

1. Перевірте наявність старих записів, налаштувань, позицій і роботу збереженого HTTPS.
2. Позначте файл важливим, перезапустіть застосунок, перевірте фільтр. Включіть його
   до групового видалення разом зі звичайним тестовим файлом: важливий має лишитися.
3. Поставте закладки під час запису до й після хвилинного поділу; завершіть запис.
   Відкрийте обидва файли, перевірте час, примітки, перехід, редагування й перезапуск.
4. Виберіть день та різні фільтри; перевірте прослухано/непрослухано й експорт групи.
5. Перевірте три варіанти видалення. При недоступній хмарі локальний файл для дії
   «З телефона і хмари» має лишитися. Перевірте скасування та повідомлення про результат.
6. Для тестової LAN-папки: HTTP без галочки має відхилятись, із підтвердженням —
   працювати. Редагування адреси/логіна має скидати галочку. Пароль вводьте на телефоні.
7. За потреби перевірте імпорт свого серверного сертифіката: правильний працює,
   чужий/прострочений або з неправильним ім’ям — відхиляється.
8. Перевірте три мови, дві теми, розклад і 30–60 хв запису з вимкненим екраном.
   Потім — годинні стики та 24–72 години з тимчасовим вимкненням мережі.
