# J7 Recorder — початковий проєкт 0.1

Власний аудіореєстратор для Samsung Galaxy J7 2016 з LineageOS / **Android 10**.
Призначення: тривалий запис із поділом на файли, обмеженням локального архіву та
завантаженням готових файлів уже встановленим застосунком Nextcloud.

**Статус: вихідний код прототипу. APK ще не зібрано; на телефоні код не запускався.**
Перевірено чисту Java-логіку планування очищення, синтаксис Java та XML. Ці перевірки
не замінюють компіляцію проти Android SDK і випробування на реальному J7.

## Що реалізовано в коді

- Запис із мікрофона: AAC у контейнері M4A, моно; 44,1 або 48 кГц;
  64 / 96 / 128 / 192 / 256 кбіт/с. Початково 128 кбіт/с, 44,1 кГц.
- Файли тривалістю від 1 до 180 хвилин; початково 60 хвилин.
- Ліміт власних локальних записів, початково 2048 МіБ. Окремо зберігається
  запас 256 МіБ вільного місця на телефоні та оцінка місця для наступного файла.
- Автовидалення найстаріших власних файлів або очікування звільнення місця,
  якщо автовидалення вимкнене.
- Постійне сповіщення з кнопкою зупинки; запис не прив’язаний до відкритого екрана.
- Повторні спроби після помилок кодека / нестачі місця з паузами 5, 15 і 60 секунд.
- Перевірка зростання поточного файла. Якщо він не збільшується понад 2 хвилини,
  сервіс намагається завершити фрагмент і повторно запустити запис.
- Збереження бажаного стану, `START_STICKY`, спроба відновлення після
  `BOOT_COMPLETED` / оновлення застосунку. Після ручного «Зупинити» запис сам не вмикається.
- Український інтерфейс, журнал із ротацією, контроль використаного місця.
- Немає бібліотек Google Play Services, Firebase, реклами, аналітики та дозволу `INTERNET`.
  GApps не потрібні нашому застосунку; мережеве завантаження виконує Nextcloud окремо.

## Як файли потрапляють до Nextcloud

Поточний `.part` зберігається в робочій папці застосунку:

`Android/data/ua.iben.recorder/files/pending/`

Після завершення запису код перевіряє, чи файл має читабельну тривалість,
і переміщує його до:

`Music/J7Recorder/`

На типовому J7 це `/storage/emulated/0/Music/J7Recorder`.
**У Nextcloud потрібно вибрати саме `Music/J7Recorder`, а не весь накопичувач.**
Там публікуються лише закриті файли `.m4a`, після чого викликається індексація медіа.
Якщо переміщення не вдалося, файл залишається в робочій папці для повторної спроби.
Ця версія використовує внутрішню спільну пам’ять телефона; довільна папка та microSD
ще не реалізовані.

Ім’я містить ідентифікатор інсталяції, дату й час початку **UTC** і випадковий суфікс.
Автовидалення враховує лише файли з ідентифікатором цієї інсталяції.
Сторонні файли та записи попередньої інсталяції після очищення даних не видаляються.
Поточний відкритий файл ніколи не є кандидатом на видалення.

**Цей прототип не отримує підтверджень завантаження від Nextcloud.** Якщо інтернету
довго немає, ліміт пам’яті може видалити ще не завантажений запис. Щоб цього не
допускати, можна вимкнути автовидалення: тоді запис призупиниться при нестачі місця
і повторюватиме спроби. Видалення лише після перевіреної передачі потребує окремого
вбудованого WebDAV-клієнта — це наступний етап, не функція поточної версії.

## Збірка на Ubuntu

Потрібні JDK 17, Python 3.11+ і Android SDK. У [Android Studio](https://developer.android.com/studio)
через SDK Manager встановити **Android SDK Platform 35** і **Build-Tools 34.0.0**.
SDK для компіляції не встановлює GApps на телефон і не додає їх до застосунку.

Розпакувати проєкт, відкрити термінал у його папці та виконати:

```bash
java -version
python3 --version
bash tools/check.sh
bash build.sh
```

`build.sh` шукає SDK у `ANDROID_SDK_ROOT`, потім `ANDROID_HOME`, потім
`$HOME/Android/Sdk`. Якщо SDK в іншому місці, вказати правильний шлях:

```bash
ANDROID_HOME=/повний/шлях/до/Android/Sdk bash build.sh
```

Перший запуск завантажить Gradle 8.9 з офіційного сервера, перевірить SHA-256,
а Gradle завантажить Android Gradle Plugin 8.7.3 та залежності збірки.
Для першої збірки потрібен інтернет на комп’ютері й прийняті SDK-ліцензії.
Gradle Wrapper JAR не включено; використовуйте наданий `build.sh`.

Якщо збірка успішна, APK буде тут:

`app/build/outputs/apk/debug/app-debug.apk`

Це тестовий APK із debug-підписом. Для наступних оновлень треба зберігати той самий
ключ підпису; для постійного використання пізніше слід створити окремий release-ключ.
Перенесення на телефон і встановлення виконуються користувачем.

## Перший запуск

1. На час тесту зупинити Yuce та інші застосунки, які використовують мікрофон.
2. Відкрити J7 Recorder і надати дозволи на мікрофон і файли.
3. У системних налаштуваннях батареї дозволити фонову роботу J7 Recorder та Nextcloud.
4. Для короткого тесту встановити 1 хвилину, 128 кбіт/с, 44,1 кГц, 2048 МіБ.
5. Запустити запис. Дочекатися кількох файлів у `Music/J7Recorder`.
6. Додати цю папку в автозавантаження Nextcloud. Перевірити, що Nextcloud приймає
   саме аудіофайли та що завантажені файли відтворюються повністю.
7. Після короткої перевірки зупинити запис, змінити інтервал на 60 хвилин і запустити знову.

## Обмеження, які потрібно перевірити на J7

- **Версія 0.1 свідомо призначена тільки для Android 10 (API 29).** На іншій версії
  ОС запуск запису відхиляється. `targetSdk 29` та legacy storage обрані для цього
  конкретного телефона; це не проєкт для публікації в сучасному Google Play.
- На межі фрагментів `MediaRecorder` зупиняється й запускається заново: можливі
  короткі прогалини. Безшовний поділ у цьому прототипі не реалізовано.
- Після аварійного вимкнення поточний MP4-фрагмент може бути пошкоджений. Читабельні
  файли при наступному старті публікуються, інші залишаються як `.failed` у робочій
  папці й враховуються в ліміті. Повного ремонту пошкодженого MP4 немає.
- На зашифрованому телефоні після перезавантаження може знадобитися перше
  розблокування PIN-кодом. Direct Boot до першого розблокування ще не реалізовано.
- «Примусово зупинити» в налаштуваннях Android припиняє роботу до наступного
  ручного відкриття/запуску. `START_STICKY` не гарантує відновлення за будь-яких умов.
- Зростання файла не доводить, що в ньому є потрібний звук. Конфлікт мікрофона,
  дзвінок або особливості аудіодрайвера LineageOS можуть давати тишу; це треба слухати.
- Безперервне захоплення аудіо утримує процесор активним і витрачає заряд.
  Багатотижневу роботу треба перевіряти на реальному обладнанні.

## Приймальні випробування

| Перевірка | Очікуваний результат |
| --- | --- |
| 10 хвилин із сегментами по 1 хвилині | Готові файли відтворюються; поточний файл не з’являється в папці Nextcloud |
| Вимкнений екран на 2 години | Зростає кількість файлів, збережено звук |
| Перезавантаження під час запису | Після доступності сховища сервіс відновлюється; у журналі є подія |
| Ручна зупинка, потім перезавантаження | Запис залишається вимкненим |
| Wi-Fi вимкнений, потім увімкнений | Nextcloud наздоганяє чергу, якщо файли ще не видалені лімітом |
| Малий ліміт з автовидаленням | Видаляються тільки найстаріші власні закриті фрагменти |
| Малий ліміт без автовидалення | Запис очікує вільне місце, файли не видаляються |
| Сторонній файл у `Music/J7Recorder` | Залишається недоторканим |
| 72 години, потім 7 діб | Перевірено пропуски, звук, нагрів, вільне місце і завантаження |

## Наступні етапи

1. Зібрати APK й усунути помилки, знайдені на J7.
2. Після вимірювання пауз вирішити, чи потрібен AudioRecord + MediaCodec із
   безперервним захопленням і перемиканням файлів.
3. Додати вбудований HTTPS/WebDAV: локальна черга, повтори, перевірка відповіді сервера,
   видалення лише підтверджено переданих файлів, пароль застосунку в Android Keystore.
4. Окремо опрацювати роботу до першого розблокування, microSD, вибір папки та
   індикацію конфлікту мікрофона.

## Перевірка цього архіву

Виконано `bash tools/check.sh`:

- 15 813 перевірок правил очищення, включно з 4000 випадковими наборами файлів;
- розбір синтаксису Java 8;
- розбір XML, наявність дозволу запису та відсутність дозволу доступу до мережі.

**Не виконано:** Android-компіляція, Android Lint, збірка APK, запуск інтерфейсу,
запис із мікрофона, перевірка Nextcloud або багатоденний тест. У середовищі
підготовки немає Android SDK, а завантаження інструментів збірки було недоступне.
