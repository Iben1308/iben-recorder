# Iben Recorder 0.2

Аудіореєстратор для Samsung Galaxy J7 2016 з LineageOS / **Android 10**, без GApps,
реклами, аналітики й сторонніх бібліотек. Готові файли передає встановлений Nextcloud.

**Версію 0.1 користувач зібрав і перевірив на телефоні: звук записувався щонайменше
22 хвилини, Nextcloud підхоплював файли. У 0.2 замінено аудіодвигун; ця версія ще
не зібрана проти Android SDK і не перевірена на J7.** Нижче наведено виконані
локальні перевірки та короткий тест для телефона.

## Що змінилося

- Назва застосунку, інтерфейсу та сповіщення — **Iben Recorder**.
- Підсилення **0…+24 дБ**, яке можна змінювати під час запису. На 0 дБ програмне
  підсилення не змінює PCM. Зміни плавні в межах одного буфера; при підсиленні
  обмежувач пом’якшує піки вище 90% шкали. Це не відновлення вже спотвореного
  мікрофоном звуку й не шумозаглушення. Почніть із +6 дБ, потім прослухайте файл.
- Постійні `AudioRecord` і AAC-кодек на всю сесію. Зміна файла не перезапускає
  мікрофон чи кодек. Попередній M4A закривається окремим потоком, поки наступний
  уже приймає аудіо. Готовий файл публікується перейменуванням, без копіювання
  великого файла через папку Nextcloud.
- Робочі файли — у прихованій папці `.temp` поза папкою автозавантаження.
- Назви готових файлів: **`2026-09-27_15-11-24(60_00).m4a`**.
- Світла, темна та системна теми. Перемикання теми не зупиняє сервіс запису.
- Індикатор рівня звуку й обмеження піків; показ кількості файлів, що завершуються.

## Оновлення вже встановленої версії

1. У старому застосунку натисніть **«Зупинити й зберегти фрагмент»**. Дочекайтеся
   готового файла в `Music/J7Recorder`.
2. Розпакуйте цей архів **в окрему папку**. Всередині залишено назву каталогу
   `j7-recorder` для зручності оновлення.
3. У своєму робочому проєкті `/home/iben/Android/project/j7-recorder` збережіть копію
   старого `app` для повернення до коду 0.1. Скопіюйте з нового архіву в цей проєкт
   **вміст `app/src/`** і **`app/build.gradle`**, замінюючи відповідні файли. Залиште
   наявні `local.properties`, Gradle Wrapper і налаштування Android Studio.
   За бажанням скопіюйте `settings.gradle`, щоб назва проєкту в IDE теж стала IbenRecorder.
4. У Android Studio виконайте Gradle Sync та `:app:assembleDebug` тим самим способом,
   яким успішно збирали 0.1.
5. Встановіть `app/build/outputs/apk/debug/app-debug.apk` **поверх старого застосунку**.
   Використовуйте той самий комп’ютер / debug-ключ. Через ADB: `adb install -r app/build/outputs/apk/debug/app-debug.apk`.
6. Не видаляйте застосунок і не очищайте його дані: це збереже налаштування, облік
   власних файлів та можливість їх контрольованого автовидалення.

Збережено `applicationId = ua.iben.recorder`, усі старі ключі налаштувань і папку
**`Music/J7Recorder`**, тому вже налаштоване автозавантаження Nextcloud працює з тією
самою директорією. Старі записи не перейменовуються. Старі власні незавершені файли
перевіряються при наступному старті; читабельні публікуються.

Якщо збережений ліміт пам’яті надто малий для двох фрагментів, збільште його або
скоротіть інтервал. Початкові 60 хв / 128 кбіт/с / 2048 МіБ підходять цій умові.

## Запис і Nextcloud

Робоча папка на типовому пристрої:

`/storage/emulated/0/Android/data/ua.iben.recorder/files/.temp/`

У ній є `.nomedia`; імена незавершених файлів закінчуються на `.part`. Прихована
папка — зручність для індексаторів; основний захист від раннього завантаження полягає
в тому, що вона **поза вибраною папкою Nextcloud**.

Після `MediaMuxer.stop()` і `release()` застосунок перевіряє тривалість M4A та
переміщує закритий файл у:

`/storage/emulated/0/Music/J7Recorder/`

**Саме цю папку слід залишити в автозавантаженні Nextcloud.** Не додавайте туди
`Android/data` або весь накопичувач. Після публікації запускається індексація медіа.
Назва містить місцеву дату й час початку фрагмента; часовий пояс фіксується на
початку сесії. У дужках — фактична тривалість із метаданих, округлена до секунди:
`(хвилини_секунди)`. Якщо назва зайнята, додається `_2`, `_3` тощо перед `.m4a`.

Видалення старих власних записів працює за локальним лімітом. Реєстр SQLite
відрізняє нові власні файли від сторонніх; старі власні файли 0.1 розпізнаються за
збереженим ідентифікатором інсталяції. Відкриті й ті, що завершуються, захищені
від очищення. Додатково зберігається резерв **256 МіБ** вільного місця на пристрої.

Як і в 0.1, застосунок **не отримує підтвердження передачі від Nextcloud**.
Автовидалення може прибрати ще не завантажений запис, якщо мережа довго недоступна.
З достатнім лімітом запас часу більший; якщо вимкнути очищення, при нестачі місця
запис зупиниться й чекатиме його звільнення. Дозвіл `INTERNET` застосунку не потрібний.

## Як працює безперервний поділ


PCM читається окремим потоком; черги мають обмежений розмір, щоб не вичерпати пам’ять
J7. Черга PCM — 64 блоки по 1024 семпли; черга закодованого AAC — 512 пакетів.
Довгі сирі WAV/PCM-файли на телефон не пишуться. Місце займають стиснуті M4A.
Межі визначаються часовими мітками семплів, а не таймером, швидкістю диска чи часом
завершення попереднього файла. Цілий AAC-пакет завжди належить одному фрагменту.
На переході файл закриває один потік, а інший пише наступний.

Якщо кодек або сховище систематично не встигають, застосунок повідомляє помилку,
зупиняє сесію й пробує відновлення через 5 / 15 / 60 секунд; аудіо не відкидається
непомітно. Після натискання «Зупинити» черги спорожнюються, кодек віддає останні
пакети, усі файли завершуються, і лише потім сервіс підтверджує зупинку.

Це прибирає заплановану зупинку мікрофона на кожній межі файла. Відсутність пропусків
на конкретному драйвері J7 ще треба перевірити прослуховуванням. Окреме відтворення
стиснених AAC-файлів також залежить від затримки/початкового стану декодера плеєра;
це не гарантія ідентичного PCM на стиках після декодування незалежних файлів.

## Коротка перевірка на телефоні

1. Після оновлення виставте **1 хвилину, 128 кбіт/с, 44100 Гц, 2048 МіБ, 0 дБ**.
2. Запишіть 5–10 хвилин постійного звуку або мовлення, також із вимкненим екраном.
   Перевірте кілька сусідніх файлів і переходи між ними. Поточний `.part` не має
   з’являтися в Nextcloud; новий `.m4a` має з’являтися приблизно щохвилини.
3. Не зупиняючи запис, змініть підсилення з 0 на +6 дБ, потім перемкніть світлу й
   темну теми. Прослухайте результат; перевірте, що запис продовжується.
4. Натисніть «Зупинити» посеред хвилини. Дочекайтеся повідомлення про збереження.
   Останній файл має містити коротший фрагмент і відповідну тривалість у назві.
5. Перевірте, що оновлення зберегло старі налаштування, записи й автозавантаження.
6. Поверніть 60 хвилин і перевірте хоча б два переходи між годинними файлами.
   Потім перейдіть до тесту із заблокованим екраном на 24–72 години.

Для перевірки очищення можна тимчасово поставити 128 МіБ, 1 хв і 256 кбіт/с:
дочекайтеся заповнення локального архіву. Переконайтеся, що прибираються найстаріші
готові записи, сторонній файл залишається, поточний запис продовжується. Окремо
перевірте поведінку з вимкненим очищенням. Автозапуск перевіряйте після цього:
активний запис → перезавантаження → перше розблокування; ручна зупинка →
перезавантаження має залишати запис вимкненим.

## Параметри та обмеження

- AAC-LC у M4A, моно, 44,1 / 48 кГц, 64 / 96 / 128 / 192 / 256 кбіт/с.
- Інтервал 1–180 хв; початково 60. Ліміт 128–32768 МіБ; початково 2048.
- Тільки Android 10 / API 29; `compileSdk 35`, `targetSdk 29`, legacy storage.
- Foreground service зі сповіщенням та частковим WakeLock для роботи з вимкненим
  екраном. Для Iben Recorder та Nextcloud залиште фонову роботу дозволеною.
- Після аварійного завершення поточний MP4 може бути непридатним. При старті
  читабельні робочі файли публікуються; решта залишаються у `.temp`, враховуються
  в ліміті й можуть бути прибрані очищенням. Повного ремонту MP4 немає.
- Після перезавантаження зашифрованого телефона може бути потрібне перше
  розблокування. Примусова зупинка через налаштування Android потребує ручного запуску.
- Дзвінок, інший власник мікрофона або драйвер можуть спричинити тишу чи помилку.
  Індикатор рівня допомагає це помітити, але не доводить якість звуку.
- Багатотижнева автономність нової версії ще не перевірена. microSD, довільна папка
  та вбудований WebDAV залишаються поза цією версією.

## Збірка нового проєкту без наявної Android Studio-конфігурації

Потрібні JDK 17, Python 3.11+, Android SDK Platform 35 та Build-Tools 34.0.0.
У корені проєкту:

```bash
bash tools/check.sh
bash build.sh
```

`build.sh` шукає SDK у `ANDROID_SDK_ROOT`, `ANDROID_HOME`, далі `$HOME/Android/Sdk`.
За потреби: `ANDROID_HOME=/повний/шлях/до/SDK bash build.sh`.
Скрипт завантажує Gradle 8.9 з офіційного сервера й перевіряє SHA-256; AGP — 8.7.3.
Першій збірці потрібні інтернет і прийняті SDK-ліцензії. APK:
`app/build/outputs/apk/debug/app-debug.apk`. Gradle Wrapper JAR до архіву не включено.

## Виконані перевірки вихідного коду 0.2

`bash tools/check.sh` перевіряє:

- правила ліміту/автовидалення, включно із захистом поточного й завершуваного файлів;
- точне збереження усіх PCM16 значень на 0 дБ, задане підсилення, обмеження піків,
  плавність змін та часткове читання буфера;
- місцеві назви, округлення тривалості, колізії і недопущення сторонніх шляхів;
- довгі часові шкали та межі AAC-фрагментів для обох частот і трьох інтервалів;
- синтаксис усіх Java-файлів, XML і відсутність дозволу `INTERNET`.

**Ці перевірки пройшли. Не виконано:** Android-компіляція/ресурсна лінковка, APK,
перевірка Android API-символів, Android Lint, запуск інтерфейсу, реальні кодеки,
запис на J7, інтеграція Nextcloud та багатоденний тест версії 0.2. У середовищі
підготовки немає Android SDK. Успішний розбір синтаксису не замінює `assembleDebug`.
