# Iben Recorder 8.1 — WebDAV, прототип 0.3-oreo.1

Проєкт для **Samsung Galaxy J7 2016 зі стоковим Android 8.1.0 (API 27)**.
Готові записи передаються прямо у Nextcloud через HTTPS WebDAV. Клієнт Nextcloud,
Google Play Services і GApps на телефоні для цього не потрібні.

Архів містить вихідний код для Android Studio. **Цю версію не зібрано в APK
і не перевірено на телефоні або справжньому сервері Nextcloud:** у середовищі
підготовки немає Android SDK. Локальні перевірки описано наприкінці.

## Що потрібно для підключення

- Сервер Nextcloud, доступний із телефона через **HTTPS**, із сертифікатом,
  якому довіряє Android. HTTP і вимкнення перевірки сертифіката не підтримуються.
- Ім’я користувача Nextcloud та окремий **пароль застосунку**.
- Створена на сервері папка, наприклад `IbenRecorder81`, із правами читання й запису.
- Повна WebDAV-адреса цієї папки. Nextcloud уже має WebDAV; окремий модуль
  на сервері для звичайного доступу до файлів не потрібний.

## Налаштування Nextcloud

1. У браузері відкрийте свій Nextcloud. У розділі **Файли** створіть папку
   `IbenRecorder81` у корені власних файлів.
2. У **Налаштуваннях файлів → WebDAV** скопіюйте свою адресу. Додайте до неї
   `IbenRecorder81/`. Приклад кінцевої адреси:

   ```text
   https://cloud.example.com/remote.php/dav/files/LOGIN/IbenRecorder81/
   ```

   Якщо Nextcloud встановлено в підкаталозі, він також має залишитися в адресі:

   ```text
   https://example.com/nextcloud/remote.php/dav/files/LOGIN/IbenRecorder81/
   ```

   Копіюйте адресу свого облікового запису: ім’я в URL може відрізнятися від
   відображуваного імені. Публічне посилання «Поділитися» для цього поля не підходить.
   Для першого тесту використайте папку без пробілів, як у прикладі.
3. Відкрийте **Особисті налаштування → Безпека** й створіть пароль застосунку
   з назвою `Iben Recorder J7`. Збережіть показаний логін і пароль: пароль
   показується лише під час створення. Вводьте його на телефоні, а не в чаті.
4. У реєстраторі відкрийте **Підключення Nextcloud (WebDAV)**, введіть адресу,
   логін і пароль та натисніть **Перевірити підключення**. Перевірка створює,
   читає, звіряє й видаляє маленький власний тестовий файл.
5. Увімкніть **Автоматично передавати готові записи**. Залиште опцію
   **Лише мережа без тарифікації**, якщо потрібна передача переважно через Wi-Fi.
   Натисніть **Зберегти підключення**.
6. Надайте дозволи на мікрофон і сховище через кнопку початку запису на
   головному екрані. Для перевірки оберіть інтервал **1 хв / 128 кбіт/с / 44100 Гц**.
   Після завершення фрагмента перевірте статус у застосунку й файл у Nextcloud.

Кнопка перевірки не зберігає введені налаштування. Після зміни полів потрібне
окреме збереження. Порожнє поле пароля під час редагування зберігає наявний пароль
лише для тієї самої адреси та користувача. Для нового підключення введіть пароль.
«Синхронізувати зараз» використовує збережене підключення й обмеження мережі.

## Як відбувається передача

1. Звук пишеться у приватну робочу `.temp`. Аудіодвигун використовує один
   `AudioRecord` і один AAC-кодек на сесію; попередній M4A завершується окремим
   потоком, поки вже формується наступний.
2. Закритий читабельний M4A публікується в `Music/IbenRecorder81/` з назвою
   на зразок `2026-09-27_23-08-23(60_00).m4a`. Це місцевий час початку запису
   та тривалість у хвилинах і секундах, округлена до секунди.
3. Фонове завдання передає готові файли, починаючи з найстаріших. Незавершені
   й пошкоджені робочі файли до черги не потрапляють.
4. Після передачі застосунок читає **весь файл із сервера** потоково та порівнює
   його розмір і SHA-256 із локальним оригіналом. Підтвердження записується в SQLite.
5. Лише після цього локальний файл може брати участь в очищенні за лімітом.

Це **одностороннє архівування**. Реєстратор не відображає й не синхронізує зміни
серверної папки назад на телефон та не видаляє серверні аудіозаписи. Якщо після
успішної перевірки видалити файл у Nextcloud вручну, застосунок не перевірятиме
його наявність перед кожним наступним локальним очищенням.

Передача не тримає весь запис у RAM і не створює другу локальну копію аудіо.
Повна перевірка додає вхідний трафік приблизно в розмір файла. Наприклад,
для запису розміром 60 МБ потрібні приблизно 60 МБ вихідного й 60 МБ вхідного
трафіку, без урахування повторів і службових даних.

## Обриви, перезапуск і конфлікти

- Черга та підтвердження зберігаються в SQLite; завдання — через Android
  `JobScheduler`. Передача працює також після ручної зупинки аудіозапису.
- Мережеві помилки викликають повтори з мінімальними паузами 30 с, 2 хв,
  10 хв і далі до 30 хв. Android може відкласти запуск довше через мережу,
  режим енергозбереження або обмеження Samsung. Це не точний таймер.
- Завершення нового запису запитує запуск черги. За порожньої черги також
  планується контрольна перевірка приблизно через 15 хвилин.
- Незавершена передача повторюється **цілим файлом**, без докачування з байтової
  позиції. Якщо сервер уже отримав цілий файл, але підтвердження загубилося,
  наступна спроба спочатку перевіряє його вміст і не надсилає повторний PUT.
- Чужий файл із тією самою назвою не перезаписується: використовується додаткова
  назва зі сталим UUID запису. Вибрана назва зберігається до початку передачі.
  Якщо конфліктує і вона, локальний оригінал залишається захищеним, у статусі — помилка.
- Зміна адреси або користувача повертає наявні локальні файли в чергу для нового
  призначення. Зміна лише пароля цього не робить.
- Сертифікат HTTPS та ім’я сервера перевіряє Android. Перенаправлення не
  виконуються: потрібно вказати кінцеву HTTPS WebDAV-адресу.
- Пароль зберігається зашифрованим AES-GCM; ключ — в Android Keystore.
  Пароль не записується в журнал. Автоматичне резервування даних застосунку вимкнене.

Тест підключення видаляє лише свій маленький файл `.iben-connection-test-…txt`
з умовою збігу ETag. При обриві тесту або відсутності потрібних прав він може
залишитися на сервері; його можна видалити вручну. Аудіозаписи не видаляються.

## Очищення пам’яті

Коли ввімкнене очищення, для звільнення місця видаляються найстаріші власні
завершені записи **з підтвердженою передачею до поточного підключення**.
Поточний фрагмент, файли на завершенні, непередані файли та файли без підтверджень
захищені. Сторонні файли застосунок не видаляє.

Це правило діє також при вимкненій або ще не налаштованій синхронізації.
Якщо непередані записи заповнили ліміт або накопичувач, запис зупиниться та
повторюватиме спроби після звільнення місця. Підтвердження передачі саме по собі
не видаляє файл: очищення відбувається, коли для запису потрібне місце.

Пошкоджені `.part` після аварійного вимкнення залишаються в `.temp` для ручного
розбору й також займають пам’ять. Застосунок не завантажує їх як готовий звук.

## Збирання та оновлення

| Параметр | Значення |
| --- | --- |
| Назва на телефоні | Iben Recorder 8.1 |
| Ідентифікатор застосунку | `ua.iben.recorder.oreo` |
| Версія | `0.3-oreo.1`, код 2 |
| Мінімальна / цільова версія | `minSdk 27`, `targetSdk 27` |
| SDK для компіляції | `compileSdk 35` |
| Готові записи | `/storage/emulated/0/Music/IbenRecorder81/` |
| Робочі файли | `Android/data/ua.iben.recorder.oreo/files/.temp/` |

Це оновлення окремого прототипу Android 8.1. Якщо він уже встановлений,
збережіть той самий debug-ключ підпису та встановіть APK **поверх нього**.
Не видаляйте застосунок і не очищайте його дані: там зберігається реєстр записів.
Міграція бази v1 → v2 зберігає записи; наявні файли спочатку не мають підтверджень
і захищені до їх перевірки через WebDAV. Записи, скопійовані вручну без реєстру
застосунку, автоматично не імпортуються.

1. Розпакуйте весь проєкт `iben-recorder-android81` в окремий каталог і відкрийте
   його через **Open** в Android Studio. Замініть весь вихідний проєкт попереднього
   прототипу 8.1, а не лише один Java-файл: змінилися також manifest і база.
2. Використайте **JDK 17**, Android Gradle Plugin **8.7.3**, Gradle **8.9**.
   У SDK Manager потрібні **Android SDK Platform 35** та **Build-Tools 34.0.0**.
3. Виконайте Gradle Sync і задачу **`:app:assembleDebug`**. Wrapper JAR не включено;
   якщо IDE просить Gradle Wrapper, скористайтеся `build.sh` або створіть Wrapper
   за допомогою Gradle 8.9.

Через термінал (JDK 17, Python 3.11+, встановлений SDK):

```bash
cd /home/iben/Android/project/iben-recorder-android81
bash tools/check.sh
bash build.sh
```

`build.sh` шукає SDK в `ANDROID_SDK_ROOT`, `ANDROID_HOME` або `$HOME/Android/Sdk`.
За потреби передайте шлях:

```bash
ANDROID_HOME=/повний/шлях/до/Android/Sdk bash build.sh
```

Скрипт завантажує Gradle з офіційного сервера та звіряє його SHA-256.
Перша збірка потребує інтернету на комп’ютері та прийнятих ліцензій Android SDK.
APK з’явиться за шляхом `app/build/outputs/apk/debug/app-debug.apk`.
Для встановлення через уже налаштований ADB:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Вихідний робочий проєкт Android 10 `j7-recorder` / `ua.iben.recorder` є окремим
застосунком. Цей прототип має власні дозволи, папку, базу та налаштування.

## Збережені функції запису

AAC-LC / M4A, моно, 44100 або 48000 Гц; 64–256 кбіт/с; фрагменти 1–180 хв;
підсилення 0…+24 дБ зі згладжуванням і обмеженням піків; світла та темна теми;
постійне сповіщення; журнал; спроби відновлення після помилки й перезавантаження.
Ліміт 128–32768 МіБ, початково 2048 МіБ; він має вміщувати два фрагменти із запасом.
Додатковий резерв на накопичувачі — 256 МіБ. Аудіодвигун із базового прототипу
для Android 8.1 не змінено.

Запис дозволений тільки на **API 27**. На стоковому Android 8.1 пункт теми
«Як у системі» може залишатися світлим; темну тему можна обрати вручну.
Це прототип для ручного встановлення.

## Перша перевірка на J7

1. Виключіть Iben Recorder 8.1 з присипляння й оптимізації батареї Samsung.
   Якщо запущений інший реєстратор, зупиніть його перед тестом мікрофона.
2. Зробіть 3–5 хвилин запису з хвилинними файлами. Дочекайтеся статусу
   «передано й перевірено», відкрийте файли у Nextcloud та прослухайте стики.
3. Вимкніть Wi-Fi на кілька фрагментів, потім увімкніть: локальні записи мають
   зберегтися й послідовно передатися після відновлення дозволеної мережі.
4. Зупиніть аудіозапис із непорожньою чергою. Черга має продовжити передачу.
5. Перевірте 30–60 хвилин із вимкненим екраном, потім переходи між годинними
   файлами та 24–72 години роботи. Протестуйте перезавантаження з першим розблокуванням.
6. Для перевірки очищення використайте тестові записи й мінімальний ліміт,
   який приймають налаштування. Переконайтеся, що у хмарі лишилися файли,
   видалені з телефона, а непередані локальні файли не зникли.

`START_STICKY`, WakeLock і завдання Android не гарантують безперервної роботи
за всіх обмежень Samsung. Після примусової зупинки через налаштування ОС треба
вручну відкрити застосунок. Аварійне вимкнення може пошкодити поточний M4A.
Робота AAC на стиках і довга автономність потребують перевірки саме на J7.

## Якщо підключення не працює

| Статус | Що перевірити |
| --- | --- |
| HTTP 401 | Логін та окремий пароль застосунку; за потреби створіть новий |
| HTTP 403 | Право доступу до папки та обмеження сервера / проксі |
| HTTP 404 / 409 | Папку створено за точною WebDAV-адресою, включно з підкаталогом Nextcloud |
| HTTP 413 | Зменште інтервал запису або збільште дозволений розмір запиту на сервері / проксі |
| HTTP 423 / 429 | Серверне блокування або обмеження частоти; заплановано повтор |
| HTTP 507 | Вільне місце та квоту користувача Nextcloud |
| HTTP 3xx | Вкажіть кінцеву HTTPS-адресу без перенаправлень |
| Помилка HTTPS | Дату телефона, ім’я хоста й ланцюжок довіри сертифіката |
| Очікування мережі | Wi-Fi не позначений тарифікованим; дозволена фонова робота |

У журналі видно помилки й назви успішно перевірених файлів. У разі збою
збережіть текст журналу та статус підключення, без паролів.

## Перевірки вихідного коду

`bash tools/check.sh` виконує:

- тести підсилення, назв, часової шкали й планування ліміту пам’яті;
- передачу справжніми HTTP-запитами до локального тестового сервера: обрив
  посеред PUT, втрату підтвердження, повтори, колізії, пошкоджений вміст,
  помилки сервера, скасування та заборону пересилання пароля при redirect;
- правила чинності підтверджень і захист файлів без них;
- застосування фактичних SQL-команд міграції до старої тестової бази;
- розбір Java-синтаксису та XML/manifest.

Тестовий транспорт спрямовує логічний HTTPS URL на HTTP loopback тільки
в тестах. Він не перевіряє TLS, Android Keystore, API Android, JobScheduler,
реальні кодеки або сервер Nextcloud. Перевірка синтаксису не є Android-збіркою.
Сторонніх бібліотек у застосунку немає.
