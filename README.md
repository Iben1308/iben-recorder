# Iben Recorder 8.1 — прототип 0.2-oreo.1

Окремий прототип для **Samsung Galaxy J7 2016 зі стоковим Android 8.1.0 (API 27)**.
Створено на основі Iben Recorder 0.2, роботу якого користувач підтвердив на Android 10.

**Саме цей прототип ще не зібрано в APK і не запущено на стоковому J7.** Перевірено
чисту Java-логіку та синтаксис; реальні кодеки, фонову роботу Samsung і Nextcloud
потрібно перевірити на телефоні. Архів містить вихідний проєкт для Android Studio.

Робочу версію Android 10 не змінено. Це окремий застосунок, не оновлення поверх неї.
Хмарні інтеграції, реклама й підготовка до Google Play до цього прототипу не додані.

## Що збережено

- Постійний запис із мікрофона: AAC-LC / M4A, моно, 44,1 або 48 кГц.
- Якість 64 / 96 / 128 / 192 / 256 кбіт/с; початково 128 кбіт/с і 44100 Гц.
- Поділ на файли 1–180 хвилин; початково 60 хвилин.
- Один `AudioRecord` і один AAC-кодек на всю сесію. На межі файла мікрофон
  не перезапускається; попередній M4A завершується окремим потоком.
- Підсилення 0…+24 дБ, зміна під час запису, плавний перехід і обмеження піків.
- Прихована `.temp` поза папкою Nextcloud; публікація лише закритих M4A.
- Назви: `2026-09-27_23-08-23(60_00).m4a` — місцевий час початку й тривалість
  у хвилинах і секундах, округлена до секунди. Колізії отримують суфікс `_2` тощо.
- Ліміт локальних записів 128–32768 МіБ; початково 2048 МіБ. Він має вміщувати
  два фрагменти із запасом. Додатковий резерв на накопичувачі — 256 МіБ.
- Очищення найстаріших власних завершених файлів. Поточні й ті, що завершуються,
  захищені; сторонні файли не є кандидатами на видалення.
- Світла й темна теми, журнал, індикатор звуку, постійне сповіщення з кнопкою зупинки.
- Спроби відновлення після помилки та перезавантаження, якщо запис був увімкнений.
- Без Google Play Services, GApps, реклами, аналітики та дозволу `INTERNET`.

## Відмінності прототипу

| Параметр | Прототип Android 8.1 |
| --- | --- |
| Назва на телефоні | Iben Recorder 8.1 |
| Ідентифікатор застосунку | `ua.iben.recorder.oreo` |
| Папка проєкту | `iben-recorder-android81` |
| Версія | `0.2-oreo.1`, код 1 |
| Мінімальна / цільова версія | `minSdk 27`, `targetSdk 27` |
| SDK для компіляції | `compileSdk 35` |
| Готові файли | `Music/IbenRecorder81/` |
| Робочі файли | `Android/data/ua.iben.recorder.oreo/files/.temp/` |

Запуск запису дозволений тільки на **API 27**. Перевірку оновлено у головному
екрані, сервісі й автозапуску. Прибрано параметри manifest і тем, призначені для
новіших версій Android. Сервіс запускається через `startForegroundService()` і
відразу показує сповіщення — цей механізм уже доступний в Android 8.

Аудіодвигун, підсилення та правила очищення залишено такими, як у базовій 0.2.
Параметри збірки не вимагають встановлювати Android 10 або SDK на телефон.
Це збірка для ручного встановлення, не для публікації в Google Play.

Пункт теми «Як у системі» реагує на нічний режим, який повідомляє ОС. На стоковому
Android 8.1 він може залишатися світлим. Темну тему можна вибрати вручну.

## Як зібрати

1. Розпакуйте архів у **новий каталог**, наприклад:
   `/home/iben/Android/project/iben-recorder-android81`.
2. В Android Studio виберіть **Open** і відкрийте цей каталог як окремий проєкт.
   Не копіюйте файли прототипу поверх робочого `j7-recorder`.
3. Залишено той самий стек збірки: Android Gradle Plugin 8.7.3, Gradle 8.9,
   JDK 17. У SDK Manager потрібні **Android SDK Platform 35** і **Build-Tools 34.0.0**.
4. Виконайте Gradle Sync і задачу **`:app:assembleDebug`**. Якщо Android Studio
   просить Gradle Wrapper, використайте наданий `build.sh` або створіть Wrapper
   з Gradle 8.9. Wrapper JAR не включено до цього вихідного архіву.

Варіант через термінал (JDK 17, Python 3.11+, встановлений Android SDK):

```bash
cd /home/iben/Android/project/iben-recorder-android81
bash tools/check.sh
bash build.sh
```

`build.sh` шукає SDK у `ANDROID_SDK_ROOT`, `ANDROID_HOME`, потім `$HOME/Android/Sdk`.
За потреби:

```bash
ANDROID_HOME=/повний/шлях/до/Android/Sdk bash build.sh
```

Скрипт завантажує Gradle 8.9 з офіційного сервера і перевіряє його SHA-256.
Для першої збірки потрібен інтернет на комп’ютері та прийняті SDK-ліцензії.
Попередження про Java 8 на новому JDK саме по собі не означає провал збірки;
для цього проєкту рекомендовано JDK 17.

APK після успішної збірки:

`app/build/outputs/apk/debug/app-debug.apk`

Перенесіть APK на J7 і дозвольте встановлення з вибраного джерела. Через ADB,
якщо вже ввімкнене USB-налагодження:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Це debug-підпис. Для наступних оновлень саме цього прототипу зберігайте той самий
ключ підпису. Окремий package означає окремі дозволи, налаштування, журнал і
реєстр власних файлів; дані попереднього застосунку не імпортуються.

## Налаштування J7 та Nextcloud

1. Відкрийте **Iben Recorder 8.1**, надайте дозволи на мікрофон і сховище.
2. Для першого тесту: **1 хв / 128 кбіт/с / 44100 Гц / 2048 МіБ / 0 дБ**.
3. У налаштуваннях батареї Samsung виключіть реєстратор і Nextcloud з присипляння
   та оптимізації. Назви пунктів залежать від версії прошивки; у застосунку є
   кнопка переходу до системних налаштувань оптимізації батареї.
4. Додайте в автозавантаження вже встановленого Nextcloud папку:

   `/storage/emulated/0/Music/IbenRecorder81/`

   Директорія створюється при першому запуску запису. Робочу папку `.temp`
   й увесь накопичувач у це правило не додавайте. Шлях можна скопіювати з інтерфейсу.
5. Запустіть запис. Коли фрагмент завершиться, файл з’явиться у вибраній папці.
   Якщо на телефоні є інший реєстратор, перед тестом зупиніть його.

Прихованість `.temp` і `.nomedia` допомагає індексаторам; основна гарантія від
раннього завантаження — розташування робочих файлів **поза папкою Nextcloud**.
Сумісність встановленого клієнта Nextcloud із Android 8.1 перевіряється окремо.

Реєстратор поки не отримує підтверджень передачі від Nextcloud. Якщо мережі довго
немає, ліміт може прибрати ще не завантажений запис. При вимкненому очищенні
запис зупиниться при нестачі місця й повторюватиме спроби після його звільнення.

## Що перевірити на стоковому Samsung

1. Запис 5–10 хвилин із хвилинними файлами: звук є у всіх файлах, назви правильні,
   незавершені файли не потрапляють у Nextcloud. Прослухайте стики сусідніх фрагментів.
2. Під час запису змініть 0 → +6 дБ та світлу → темну тему. Запис має продовжитися.
3. Зупиніть посеред хвилини, дочекайтеся завершення: останній коротший файл має
   відтворюватися повністю. Підсилення збільшує також шум; за спотворень зменшіть його.
4. Повторіть із вимкненим екраном на 30–60 хвилин. Потім перевірте два переходи
   між годинними файлами, і лише після цього — 24–72 години автономної роботи.
5. Якщо мікрофон або кодек видають помилку, збережіть текст **«Журналу роботи»**;
   зупиніть запис і перевірте другу частоту (48000 замість 44100 Гц).
6. Перезавантаження під час активного запису: після першого розблокування сервіс
   має спробувати відновитися. Після ручної зупинки він має залишитися вимкненим.

`START_STICKY`, WakeLock і сповіщення не гарантують роботу за всіх обмежень Samsung.
Аварійне вимкнення може пошкодити поточний MP4; читабельні робочі файли перевіряються
при наступному старті. Примусова зупинка через налаштування ОС потребує ручного
відкриття застосунку. Безперервний кодек не гарантує ідентичного декодованого PCM
на стиках незалежних AAC-файлів у кожному плеєрі.

## Перевірки цього архіву

Локально виконано `bash tools/check.sh`: тести підсилення, часових меж, назв та
очищення, розбір синтаксису Java й XML. Перевірено, що зміни зроблено лише в
окремому проєкті, а аудіодвигун збігається з базовою версією 0.2.

**Не виконано:** компіляція проти Android SDK, Android Lint, збірка APK,
запуск на Android 8.1, перевірка кодека Samsung, фонової роботи чи синхронізації.
У середовищі підготовки немає Android SDK. Сумісність API за документацією та
успішні Java-тести не замінюють перевірку APK на J7.
